## Возможности

### Три режима работы (вкладки)

| Вкладка | Описание |
|---|---|
| **Инвентаризация** | Сканирование ОС в рамках акта инвентаризации |
| **Поиск ОС** | Быстрый поиск любого ОС по штрих-коду или инв. номеру |

### Сканер инвентаризации
- Сканирование штрих-кодов через камеру
- Ручной ввод инвентарного номера
- Статусы результата: **Найден**, **Не на месте**, **Уже просканирован**, **Не найден**
- Перемещение ОС: смена кабинета и/или сотрудника (из списка или вписать вручную)
- Быстрое повторное перемещение (применить предыдущее одной кнопкой)
- Отмена сканирования (возврат ОС в статус «Не проверен»)
- История сканирований за сессию (до 50 записей)
- Статистика по локациям
- Тактильная обратная связь (haptics)

## Веб-версия (HTTPS)

Адрес: **https://10.22.5.53/scanner/** (или `https://ukk-hb-ws-obsvm.nis.edu.kz/scanner/`, если имя резолвится в сети телефона).

Камера и service worker в браузере работают только по HTTPS, поэтому веб-версия отдаётся только по нему. API — на том же адресе (`/api/` проксирует nginx), так что поля «Адрес сервера» в веб-версии нет.

### Сборка и выкладка

```bash
npm run build:web
```

Скрипт `scripts/build-web.js` собирает `expo export` во временную папку, добавляет манифест, иконку и service worker (шаблоны в `pwa/`) и копирует всё в `dist/`: сначала бандлы, `index.html` и `sw.js` в конце. Сайт при этом не пропадает, а перезапуск nginx не нужен.

### nginx

Блок `server { listen 443 ssl; … }` в `C:/nginx/conf/nginx.conf`:
- `/scanner/` → `dist/` этого репозитория (SPA: любой путь отдаёт `index.html`);
- `/api/`, `/uploads/`, `/install/` → бэкенд `127.0.0.1:3000`;
- `/` → редирект на `/scanner/`.

nginx запущен под PM2 с правами администратора, поэтому после правки конфига нужна **PowerShell от администратора**:

```powershell
C:\nginx\nginx.exe -t -p C:\nginx\
C:\nginx\nginx.exe -s reload -p C:\nginx\
```

### Сертификат

Свой CA школы, все файлы лежат в `C:/nginx/conf/ssl/`:

| Файл | Что это |
|---|---|
| `ca.crt` / `ca.key` | корневой CA «NIS Oskemen local CA», до 2036 года. **`ca.key` никому не отдавать** |
| `server.crt` / `server.key` | сертификат nginx на `10.22.5.53` и `ukk-hb-ws-obsvm.nis.edu.kz`, **до 27.12.2028** |

`ca.crt` ставится на телефон один раз, инструкция на странице `/install/`, там же кнопка скачивания (`nis-oskemen-ca.crt`).

Перевыпуск серверного сертификата (825 дней — больше iOS не примет). Git Bash, в `C:/nginx/conf/ssl`:

```bash
MSYS_NO_PATHCONV=1 openssl req -newkey rsa:2048 -sha256 -nodes -keyout server.key -out server.csr \
  -subj "/C=KZ/O=NIS Oskemen/CN=10.22.5.53"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out server.crt -days 825 -sha256 -extfile server.ext
```

Затем перезагрузить nginx. CA не меняется, поэтому на телефонах переустанавливать ничего не нужно.

### Ограничения

- Камера в браузере (expo-camera web) читает **только QR-коды**. Штрихкоды наклеек — ручной ввод, либо APK / Expo Go.
- Сертификат свой: телефон без установленного `ca.crt` покажет предупреждение, и офлайн работать не будет.

## Оффлайн-режим

Сканирование актов работает без сети. Всё это — модуль акта `constants/act`: экраны видят `acts.list()`, `useAct(id)` с позициями и три действия (`scan`, `relocate`, `cancel`); копия акта, очередь и досылка спрятаны внутри. Модуль не импортирует React Native — сервер и хранилище подаются адаптерами, поэтому тесты гоняют его целиком без эмулятора. Термины (акт, позиция акта, копия акта, очередь, досылка) — в `CONTEXT.md`.

- **Копии данных.** Удачные ответы сервера (список актов, акт с позициями, кабинеты, сотрудники) сохраняются на телефоне. На Android и iOS — файлами в `documentDirectory/offline/`: у AsyncStorage на Android лимит ~2 МБ на значение и 6 МБ всего, а акт «Вся школа» туда не влезет. На вебе — в localStorage.
- **Когда сохраняется.** Вкладка «Акты» сохраняет все запущенные акты, пока есть связь; экран сканера сохраняет свой акт при открытии.
- **Очередь.** Без связи (нет ответа, таймаут 6 с или 502/503/504) скан, перемещение и отмена встают в очередь в AsyncStorage. Результат на экране считается по копии акта теми же правилами, что на бэкенде. Код не из акта показывается как «Нет в акте — проверим при отправке».
- **Досылка.** Идёт сама: при старте, при возврате в приложение и каждые 15 секунд, строго по порядку. Сканы уходят с полем `scannedAt` — временем скана на телефоне (бэкенд принимает его в пределах недели). Если сервер отказал (например, акт завершён), операция попадает в список «Сервер не принял».
- **Повторы безопасны.** Повторный скан сервер вернёт как «уже отсканирован», повторное перемещение идемпотентно, а повторная отмена излишка даёт 404 и тоже считается успехом.
- **Вход без сети.** Работает для того же логина, если введён тот же пароль (сверяется с отпечатком с прошлого входа) и refresh-токен ещё жив (7 дней).
- **Очередь привязана к логину.** После выхода она ждёт входа своего автора: сервер пишет в акт того, чей токен.

В веб-версии само приложение без сети открывает service worker (`pwa/sw.js`). В Expo Go оффлайн работает, только пока приложение открыто: холодный старт без Metro невозможен.

## Конфигурация сервера

При первом запуске приложение показывает экран входа, где нужно указать:

- **Имя** — будет записано в акт инвентаризации
- **Адрес сервера** — IP и порт без `http://` и `/api`

Пример: `10.216.209.118:8888`

Данные сохраняются в AsyncStorage и восстанавливаются при следующем запуске. Изменить можно через кнопку **Выйти** → повторный вход с новыми данными.

## API

Приложение работает с REST API бэкенда. Базовый URL формируется динамически: `http://<host>/api`.

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/auth` | Вход (учётная запись AD) — access и refresh токены |
| `POST` | `/auth/refresh` | Обновление токенов |
| `GET` | `/inventory-sessions` | Список актов инвентаризации |
| `POST` | `/inventory-sessions` | Создание акта |
| `GET` | `/inventory-sessions/:id` | Акт с позициями |
| `POST` | `/inventory-sessions/:id/start` | Запуск; так же `pause`, `resume`, `complete`, `cancel` |
| `POST` | `/inventory-sessions/:id/scan` | Скан ОС; `scannedAt` — время скана, сделанного без связи |
| `PATCH` | `/inventory-sessions/:id/items/:itemId` | Перемещение: кабинет и/или сотрудник |
| `POST` | `/inventory-sessions/:id/items/:itemId/unscan` | Отмена скана |
| `GET` | `/inventory/assets` | Поиск ОС по штрих-коду или инв. номеру |
| `GET` | `/inventory/locations` | Справочник кабинетов |
| `GET` | `/inventory/names` | Справочник сотрудников |

## Сборка APK для Android

> ⚠️ Папка `android` генерируется заново при каждом `prebuild`. После этого нужно вручную настроить HTTP-доступ к серверу — два способа ниже.

### Шаг 1 — Сгенерировать папку android

```bash
npx expo prebuild --platform android
```

---

### Шаг 2 — Разрешить HTTP-запросы к серверу

Android 9+ по умолчанию блокирует HTTP. Есть два способа:

#### Способ А — через AndroidManifest.xml (проще, рекомендуется)

Открыть файл:

```
android\app\src\main\AndroidManifest.xml
```

Добавить `android:usesCleartextTraffic="true"` в тег `<application>`:

```xml
<application
  android:usesCleartextTraffic="true"
  android:label="@string/app_name"
  ...
>
```

✅ Делается один раз. Разрешает HTTP для любого IP — удобно для корпоративной сети.

---

#### Способ Б — через network_security_config.xml (для конкретного IP)

1. Создать папку `xml`, если её нет:

```
android\app\src\main\res\xml\
```

2. Создать файл `network_security_config.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">192.168.1.100</domain>
    </domain-config>
</network-security-config>
```

Заменить `192.168.1.100` на реальный IP вашего сервера.

3. Подключить файл в `AndroidManifest.xml`:

```xml
<application
  android:networkSecurityConfig="@xml/network_security_config"
  ...
>
```

> ⚠️ Этот файл нужно создавать заново после каждого `npx expo prebuild` и обновлять IP если он изменился.

---

### Шаг 3 — Собрать APK

```bash
cd android
gradlew assembleRelease
```

Готовый APK будет здесь:

```
android\app\build\outputs\apk\release\app-release.apk
```

После сборки готовый APK нужно передать на телефон и установить вручную.

### Шаг 1 — Передать файл на телефон

Выберите удобный способ:

| Способ | Как |
|---|---|
| **USB** | Подключить телефон, открыть папку телефона в Проводнике, скопировать APK |
| **Telegram** | Отправить APK себе в «Избранное» или в рабочий чат |
| **Google Drive** | Загрузить на диск, открыть на телефоне через приложение Drive |

### Шаг 2 — Разрешить установку из сторонних источников

На Android по умолчанию запрещена установка APK не из Play Store.

**Android 8 и выше:**
1. Открыть скачанный APK через файловый менеджер
2. Появится запрос — нажать **Настройки** → включить **Разрешить из этого источника**
3. Вернуться назад и нажать **Установить**

**Или заранее через настройки:**
```
Настройки → Приложения → Специальный доступ → Установка неизвестных приложений
```
Разрешить для вашего файлового менеджера или браузера.

Открыть файл `app-release.apk` в файловом менеджере → **Установить** → **Открыть**.

## Частые проблемы

### Приложение не подключается к серверу

- Убедитесь, что телефон и сервер в одной Wi-Fi сети
- Проверьте правильность IP и порта на экране входа
- Если используется HTTP — убедитесь, что настроен `usesCleartextTraffic` (см. Шаг 2)
- Проверьте, что сервер запущен и доступен: откройте `http://<IP>:<PORT>/api` в браузере телефона

### Камера не открывается

- Зайдите в **Настройки → Приложения → Инвентаризация → Разрешения** и разрешите доступ к камере
- Или нажмите кнопку **Разрешить** на экране сканирования

### `gradlew assembleRelease` падает с ошибкой

- Убедитесь, что установлен JDK 17: `java -version`
- Проверьте переменную окружения `JAVA_HOME`
- Попробуйте очистить сборку: `cd android && gradlew clean`, затем повторить

### После `prebuild` пропала настройка HTTP

- Это ожидаемо — `prebuild` перегенерирует `android/` с нуля
- Повторите Шаг 2 после каждого `prebuild`
